Mathematical foundations

Rao-Wu rescaled bootstrap

Primary sampling units are resampled with replacement within each stratum, respecting the design of the survey. Rescaled weights are recomputed per replicate and every estimator is re-run, so intervals reflect clustering and stratification rather than assuming simple random sampling.

  • 1,000 replicate draws per estimate
  • Percentile 95% intervals from the replicate distribution
  • Design-aware: PSU and stratum identifiers are carried through the pipeline

Holm-adjusted weighted Mann-Whitney effect size

Group comparisons report a weighted Mann-Whitney effect size: the probability that a randomly chosen member of one group has a larger value (0.5 means no difference). P-values come from the Rao-Wu bootstrap and are corrected with the Holm step-down procedure across the contrasts in a family. Rank-based, so no normality assumption on skewed quantities such as age gaps.

  • Rank-based, robust to outliers and ordinal measures
  • Holm correction applied across all comparisons in a lens
  • Monotone association reported via Spearman rank correlation

Honest limitations

LIMITATIONS.md 
# Limitations and caveats

## 1. Derived Mahr benchmark
- The Mahr reference is a derived gold / CPI benchmark,
  not an observed transaction value. Treat it as a
  scale indicator, not a measurement.

## 2. Cross-sectional associations
- HIES is a single-period survey. Every result is an
  association, never a causal effect.
- Cohort and age effects cannot be separated.

## 3. Living-with-parents exclusion
- Couples living with parents are not captured as
  head-spouse pairs in HIES, so the sample excludes
  them. Findings describe head-spouse households only.

## 4. Interval coverage
- Intervals quantify sampling variance under the
  design. They do not cover measurement or coding error.

## 5. What HIES cannot show
- No sect, caste or ethnicity variable, so
  inelasticity by sect or caste is not measured.
- Mahr is derived from month-end gold
  (September has one source) and ten months of CPI.

-- core.couples: idempotent upsert from stg.couples_stage
MERGE core.couples AS t
USING stg.couples_stage AS s
   ON t.couple_id = s.couple_id
WHEN MATCHED THEN
  UPDATE SET t.weight = s.weight, t.age_gap = s.age_gap, ...
WHEN NOT MATCHED BY TARGET THEN
  INSERT (couple_id, weight, ...) VALUES (s.couple_id, s.weight, ...);
